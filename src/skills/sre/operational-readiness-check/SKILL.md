# SRE 运行准备度检查

## 适用范围

这是对服务当前能力和证据完整度的计划性检查，不是活动故障排查，也不负责复盘一个已发生事件。复盘行动项的后续核验可以作为本次检查的范围，但时间线、因果分析和响应回顾仍由 `sre/postmortem` 负责。

## 检查范围

在检查前确认服务/平台名称、环境、关键业务流程、负责人、最近变更和本次检查目标。用户可能要求上线准备、周期巡检、故障复盘后的改进核验或单一主题检查；按目标裁剪清单。

## 检查项

逐项收集文档、配置、告警/监控记录、演练记录或工具输出。输出状态只能是 `已验证`、`存在问题`、`未验证`、`不适用`。

1. **服务目标与影响**
   - 是否定义关键用户旅程、服务所有者、依赖关系和业务影响范围。
   - 是否有可测量的 SLI/SLO、错误预算或业务侧可用性目标；阈值由服务团队提供，不自行发明。
2. **监控与告警**
   - 核对用户可见症状是否有可观测指标、告警责任人、阈值依据、抑制/去重方式和升级路径。
   - 查清指标、日志、追踪或事件数据的时间覆盖、缺口和访问权限。
3. **故障处置**
   - 是否有明确值班与事件负责人、严重度准则、沟通渠道、业务状态更新责任和服务 runbook。
   - runbook 是否包含前置条件、只读诊断、回退/升级条件、验证成功判据和维护日期。
4. **容量与退化行为**
   - 是否有近期利用率、容量上限、配额、扩容时延和预计峰值依据。
   - 是否识别关键依赖、超时/重试/熔断行为和降级策略；没有历史数据时标为未验证。
5. **数据保护与灾难恢复**
   - 核对备份范围、保留周期、访问隔离、恢复目标（RPO/RTO）和最近一次真实恢复演练证据。
   - 仅有“备份任务成功”不能证明数据可恢复；没有演练记录时标为未验证。
6. **发布与变更安全**
   - 是否有可追踪的制品版本、分阶段发布/健康门禁、回滚方案和发布后验证。
   - 发布失败时区分构建、制品、部署和业务健康验证；避免只凭流水线绿色判断业务可用。
7. **安全与访问边界**
   - 是否使用最小权限、凭据轮换/托管、审计和环境隔离；检查过程不读取或展示秘密值。

## 结果判定

- 只有找到可核对的证据，且证据适用于本次目标环境，才能标记“已验证”。
- 文档缺失、工具未接入、权限不足、数据过期或只看到期望配置时标记“未验证”，并说明补证方式。
- 检查项确实不适用时写明原因；不要为了完成清单而强行标成通过。
- 依据用户/团队提供的策略判断风险级别。本 Skill 不替团队设置统一合规阈值。

## 输出格式

```text
对象 / 环境 / 检查时间：
检查范围：
总体结论：可接受 / 有风险 / 证据不足（依据）
检查项：检查项 | 状态 | 证据 | 风险 | 建议负责人/后续证据
高优先级风险：
未验证项：
不适用项及理由：
```

## 工具约定

优先使用当前 `available_tools`、用户提供的配置或经过授权的文档。当前工具面不覆盖的 SLO、指标、备份、网络、依赖关系等检查不得伪装成已执行；应列出需要接入的 Prometheus、日志、备份或资产数据源。
